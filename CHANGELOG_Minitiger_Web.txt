Minitiger Web – Phase 18.5.1
Plugin Release ZIP Hotfix

AUSGANGSSTAND
- Jellyfin Server / Web: 12.1.
- Separater Plugin-Build `Build Minitiger Virtual Sync Plugin` ist auf GitHub grün durchgelaufen.
- Erster manueller Release-Workflow `Release Minitiger Virtual Sync Plugin` schlug fehl.

FEHLERURSACHE
- Der Workflow exportierte die Variable `ZIP=Minitiger.VirtualSync_1.0.3.0.zip`.
- Das auf GitHub Actions verwendete Info-ZIP wertet die Umgebungsvariable `ZIP` selbst aus.
- Dadurch wurde `Minitiger.VirtualSync_1.0.3.0.zip` an einem anderen Ort/Namen erzeugt als vom Workflow erwartet.
- Der nachfolgende `md5sum` suchte deshalb vergeblich nach `$RUNNER_TEMP/Minitiger.VirtualSync_1.0.3.0.zip` und brach mit Exit Code 1 ab.

FIX
- Reservierte Umgebungsvariable `ZIP` vollständig entfernt.
- Neuer neutraler Variablenname: `ARCHIVE_NAME`.
- Publish, MD5, Source-URL, GitHub Release und Summary verwenden jetzt konsistent `ARCHIVE_NAME`.
- Nach dem ZIP-Bau prüft `test -s`, dass das erwartete Release-Archiv tatsächlich existiert und nicht leer ist.

NICHT VERÄNDERT
- Plugin-Code / Virtual-Sync-Logik.
- Jellyfin Plugin ABI (`12.0.0.0`).
- Plugin-Version / geplantes erstes Release `1.0.3.0`.
- Sidecar, UI, Trailer, Audioflags, Manga und Playback.

STATUS
- Fix ist statisch/lokal verifiziert, aber der echte GitHub Release-Workflow muss vom Nutzer erneut getestet werden.
