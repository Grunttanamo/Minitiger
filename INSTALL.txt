MINITIGER WEB – PHASE 18.4.1
Sidecar Browser Entry Hotfix

VORAUSSETZUNG
- Branch: minitiger-v12.1
- Phase 18.4.0 Sidecar ist bereits vorhanden.
- Jellyfin Server / Webbasis: 12.1.

ÄNDERUNGEN
- Browser-Aufruf von `/`, `/web` und `/web/` wird jetzt auf
  `/web/index.html` normalisiert.
- Damit soll die rote Jellyfin-Seite "Software Failure / Seite nicht gefunden"
  beim kurzen Browser-Link verschwinden.
- Compose-Beispiel bekommt einen frei konfigurierbaren Host-Port mit Default
  8098. Der Container-Port bleibt immer 80.
- Keine Minitiger-UI-, Datenbank-, Appdata- oder Serverdateien werden verändert.

INSTALLATION AUF DEM RASPBERRY PI

1) In das Repository wechseln:
   cd ~/minitiger-web

2) Patch entpacken:
   unzip -o ~/minitiger_native_phase18_4_1_sidecar_browser_entry_hotfix.zip -d ~/minitiger-web

3) Prüfen:
   chmod +x VERIFY_PATCH.sh
   ./VERIFY_PATCH.sh

4) Committen und pushen:
   git add docker/minitiger-sidecar.conf.template \
     docker-compose.sidecar.example.yml SIDECAR_SETUP.md \
     INSTALL.txt CHANGELOG_Minitiger_Web.txt files.txt VERIFY_PATCH.sh \
     Minitiger_Gedaechtnis
   git commit -m "Fix Minitiger sidecar browser entry"
   git push

Der Push löst automatisch `Build Minitiger Sidecar` aus, weil die nginx-
Template-Datei geändert wurde.

5) Nach grünem GitHub-Workflow lokales Image aktualisieren:
   docker pull ghcr.io/grunttanamo/minitiger-web:latest
   docker stop minitiger-web 2>/dev/null || true
   docker rm minitiger-web 2>/dev/null || true

   docker run -d \
     --name minitiger-web \
     --restart unless-stopped \
     -p 8098:80 \
     -e JELLYFIN_URL="http://host.docker.internal:8096" \
     --add-host=host.docker.internal:host-gateway \
     ghcr.io/grunttanamo/minitiger-web:latest

6) Browser-Test:
   http://192.168.178.50:8098

ERWARTUNG
- Der kurze Link soll direkt Minitiger laden.
- Kein manuelles `/web/index.html` mehr nötig.
- Normales Jellyfin auf :8096 bleibt unverändert.
