MINITIGER WEB – PHASE 18.4.3
GitHub Hero Banner + Fast GHCR Metadata

VORAUSSETZUNG
- Branch: minitiger-v12.1
- Phase 18.4.2 ist bereits eingespielt.
- Jellyfin Server / Webbasis: 12.1.
- GHCR-Package `minitiger-web` ist Public.

ZIEL
- Minitiger bekommt eine eigene hübsche README mit Banner statt der sichtbaren
  Upstream-Jellyfin-Präsentation.
- README-/Banner-Änderungen sollen KEINEN langen Docker-Multi-Arch-Build mehr
  auslösen.
- Die kurze GHCR-Package-Beschreibung kann künftig über einen manuellen,
  schnellen Metadata-Workflow geändert werden, ohne Minitiger neu zu bauen.

NEU
- docs/assets/minitiger-banner.gif
  -> echtes animiertes 2-Frame-GIF aus den bereitgestellten Minitiger-Motiven.
- docs/assets/minitiger-banner.png
  -> statischer Fallback.
- README.md
  -> Hero-Banner, Badges, Sidecar-Erklärung, Quick Start, Unraid, Tags,
     Kompatibilität, Credits/Lizenz.
- .github/workflows/minitiger-package-metadata.yml
  -> manueller Metadata-only Workflow für GHCR.
- Build Minitiger Sidecar wird bei README-/Doku-Änderungen nicht mehr gestartet.

INSTALLATION AUF DEM RASPBERRY PI

1) In das Repository wechseln:
   cd ~/minitiger-web

2) Patch entpacken:
   unzip -o ~/minitiger_native_phase18_4_3_github_hero_metadata_quickupdate.zip -d ~/minitiger-web

3) Prüfen:
   chmod +x VERIFY_PATCH.sh
   ./VERIFY_PATCH.sh

4) Committen und pushen:
   git add README.md docs/assets \
     .github/workflows/minitiger-sidecar.yml \
     .github/workflows/minitiger-package-metadata.yml \
     SIDECAR_SETUP.md INSTALL.txt CHANGELOG_Minitiger_Web.txt \
     files.txt VERIFY_PATCH.sh Minitiger_Gedaechtnis

   git commit -m "Add Minitiger banner and fast package metadata workflow"
   git push

WICHTIG NACH DEM PUSH
Der sichtbare Package-README-Block hängt am verknüpften Repository. Damit die
Minitiger-README statt der alten Jellyfin-README erscheint, den Default Branch
auf `minitiger-v12.1` stellen:

GitHub -> Minitiger -> Settings -> Default branch -> Wechsel-Symbol
-> minitiger-v12.1 -> Update -> bestätigen.

DAS LÖST KEINEN DOCKER-BUILD AUS.

PACKAGE-BESCHREIBUNG OHNE DOCKER-BUILD ÄNDERN
GitHub -> Minitiger -> Actions -> Update Minitiger Package Metadata
-> Run workflow -> Description bearbeiten -> Run workflow.

Dieser Workflow kompiliert Minitiger NICHT neu. Er verwendet das vorhandene
Multi-Arch-Image und aktualisiert nur die GHCR-Index-Metadaten für `latest`
und `12.1`.
